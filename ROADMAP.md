# Shem Roadmap

This is the single forward-looking plan. Phases execute **one at a time, in
order**; a phase is marked complete only when its exit criteria are verified.
Each phase gets a design spec and an implementation plan before code (local
development artifacts, not part of the public tree). The two tracks at the
bottom run in parallel and never block a phase.

**Status legend:** `next` · `in progress` · `done` · `pending`

---

## Phase 1 — Trust the Front Door `done`

Close the request-origin and Elixir-execution gaps found in the 2026-07-02
security review, and fix fresh-clone first impressions.

**Scope**
- Host/Origin guard on the `:4000` listener: reject requests whose `Host`
  header is not loopback / the configured host (kills DNS-rebinding attacks
  against the local server). Optional bearer token, generated by `shem setup`,
  required whenever the bind address is non-loopback.
- Elixir AST deny-scan before `Code.compile_string` in the graduation gate —
  stopgap until Phase 5. Denies `System`, `File`, `:os`, `Port`, `Code`, and
  `:erlang` escape hatches (`open_port`, external `spawn`) in tool and test
  source. Applies equally to agent-authored tools and installed packs.
- Green default suite: add `:distributed` to the `ExUnit.start(exclude: ...)`
  list in `test/test_helper.exs` (the tests already carry
  `@moduletag :distributed`); add a `mix test.dist` alias documenting the
  `--sname` run.
- README honesty: a determinism-boundary paragraph (replay-from-log is
  deterministic; fork-and-continue re-rolls live; side-effecting tools noted)
  and an Elixir-sandbox caveat that Phase 5 removes.

**Exit criteria**
- A test proves non-local `Host` headers are rejected.
- A test proves a `System`/`File`-calling Elixir tool fails the gate.
- Fresh-clone `mix test` is green; `mix test.dist` runs the distributed set.
- README claims survive a skeptical read.
- **Gates the Dogfood track** (see below).

## Phase 2 — Human Co-Driver `done`

Execute the existing co-driver design (2026-07-02 spec + plan): a human at the
WebUI injects a running agent's next turn; the fork-lane co-driver rail ships
as the reusable primitive. Validate the plan against current master before
starting (its own stated note).

**Exit criteria:** inject a turn from the browser into a live client-brain
agent; the agent acts on it; the event is in the log like any other turn.

## Phase 3 — Agent Regression Testing `done`

`shem replay --check`: golden sessions from recorded runs. Re-run a session
against a new model / prompt / tool version, report *where* it diverged,
exit non-zero on unexpected divergence — agent behavior CI. Recombines
shipped primitives (Branch, Replay diff, chain verify, WebUI divergence
detection).

**Exit criteria:** a recorded development session (from the Dogfood track)
replays with a divergence report; a deliberate prompt change is caught; the
exit code is usable in CI.

## Phase 4 — Verifiable Ops `done`

- **`shem attest <session>`** `done` (2026-07-03) — export a self-verifying
  bundle: `events.jsonl` (canonical JSON), `tools/<sha256>` exact tool sources,
  `manifest.json` (portable_head + beam_head, two-head trust model), a
  stdlib-only `verify.py`, and a POSIX-sh/`sha256sum` fallback. Runs on a
  machine with neither Shem nor Erlang. Live path attests a running session via
  `rpc` (no stop needed); stopped path boots ephemeral. Suite 1225.
- **Segment-digest GC** `done` (2026-07-04) — prune old events by segment into
  a coalescing rollup digest that stays in the hash chain, triggered
  automatically on append (`keep_events`, default 100k) or manually
  (`shem gc <session>` / `mix shem.gc`); verification and attest bundles stay
  intact across a prune. Suite 1257.

**Exit criteria:** disk usage bounded under continuous use; chain verification
passes across a GC; an attest bundle verifies offline on a clean machine.
Both are prerequisites for any production-readiness claim.

## Phase 5 — Elixir Parity Sandbox `pending`

Elixir tool graduation and invocation run with the same isolation as
Python/JS/Go: container-executed or on a disposable peer node (the
`Executor.run_remote` plumbing exists). Replaces the Phase 1 AST scan as the
enforcement layer (the scan may remain as a fast pre-filter).

**Exit criteria:** no code path compiles third-party or agent-authored Elixir
source into the host BEAM; the README sandbox caveat is removed.

## Phase 6 — Observability Surface `pending`

WebUI live monitoring panel (per-node health via `:os_mon`, running agents,
trust bands) and a read-only graduated-tool inspector (trust band, source,
test results, live graduation view).

**Exit criteria:** node mesh and agent health visible live in the browser;
every graduated tool inspectable without touching the filesystem.

## Dogfood track (standing practice — gated on Phase 1)

Shem is used to further Shem's own development. Tool-server mode (an external
brain such as Claude Code over MCP) is the practice; autonomous local-LLM
development is a Phase-5+ aspiration, not a near-term claim.

- Every development session on Shem runs with Shem connected via MCP
  (`shem start` + `claude mcp add`); structural codebase questions go through
  `graphify_query` first.
- Each phase's execution uses at least one Shem capability for its own work:
  Phase 2 — client-brain explorer agents during co-driver development;
  Phase 3 — `replay --check` validated on real dev sessions; Phase 4 —
  `attest` a real session from this track.
- The token bench gets its number from these sessions, not a synthetic run.

**Friction log** (anything that made Shem awkward to reach for — one line
each; this is the live stickiness measurement):

- 2026-07-03 (Phase 3): recording a golden outside a running `shem` is awkward —
  `mix run` exits without graceful shutdown so DETS never flushes, and PresetStore
  doesn't persist cross-process. Goldens must come from a real `shem start` session,
  not an ad-hoc script. (`shem attest`, Phase 4, is the intended portable path.)

- 2026-07-03 (browser-tools pack): container executor hardcodes `--network=none` and
  `python:3.12-slim`, which is correct for most tools but blocks browser-automation
  tools that need network + playwright browsers. Workaround: `executor.backend: local`.
  Per-tool sandbox profiles (network mode, container image per runtime) needed.
  Filed by big-pickle.

- 2026-07-03 (Phase 4 attest): building a scriptable `shem attest` verb over the
  live node was awkward — release `rpc` (OTP 29 / Elixir 1.19) ALWAYS exits 0, does
  not surface the evaluated expression's return value, and does not propagate a
  raise as a non-zero exit; only `IO` from inside the call reaches the caller. So a
  read-only CLI action against a running daemon can't report failure via exit code
  the obvious way — we print a sentinel line and have the shell wrapper key the exit
  code on it. A first-class "release rpc that returns an exit code without halting
  the node" would remove this dance.

- 2026-07-03 (Phase 4 Dogfood, OPEN): "attest a real session from this track" not yet
  done live — the running instance is an older 0.4.0 without `attest`; exit criteria
  are met by the e2e (real `verify.py`), but the live-Dogfood attest awaits a rebuilt
  `shem start` of this version.
